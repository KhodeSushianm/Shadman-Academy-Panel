# پنل مدیریت آکادمی شیما شادمان

اپلیکیشن رومیزی برای مدیریت دانش‌آموزان، برنامه‌های مطالعاتی، نتایج آزمون‌ها و یادداشت‌های مشاور.

رابط کاربری کاملاً فارسی و راست‌به‌چپ، و **به‌طور کامل آفلاین** — هیچ درخواست شبکه‌ای در زمان اجرا ندارد.

---

## ویژگی‌ها

| بخش | امکانات |
|---|---|
| **داشبورد** | آمار کلی، نمودار روند تراز آزمون‌ها، فعالیت‌های اخیر |
| **دانش‌آموزان** | ثبت/ویرایش/حذف، جستجو، فیلتر بر اساس وضعیت، پروفایل کامل در کشو |
| **برنامه‌های مطالعاتی** | ثبت برنامه، تغییر وضعیت انجام، مدت‌زمان |
| **آزمون‌ها** | ثبت نتیجه، محاسبه‌ی خودکار میانگین تراز دانش‌آموز |
| **یادداشت‌ها** | یادداشت مشاور با تاریخ جلالی |
| **تنظیمات** | انتخاب پوشه‌ی ذخیره‌سازی، خروجی دیتابیس، بازنشانی، حالت روشن/تاریک |

---

## اجرا

```bash
npm install
npm start
```

نیازمندی‌ها: Node.js نسخه‌ی ۲۰ یا بالاتر.

### اولین اجرا

در نخستین راه‌اندازی، پنجره‌ای برای **انتخاب پوشه‌ی ذخیره‌سازی** باز می‌شود. همه‌ی داده‌ها در فایلی به نام `shima-academy.sqlite` داخل همان پوشه نگه داشته می‌شوند — یعنی داده‌های شما روی دیسک خودتان است، نه در یک پایگاه‌داده‌ی ابری.

اگر پوشه را لغو کنید، برنامه در حافظه کار می‌کند و داده‌ها پس از بسته شدن از دست می‌روند.

---

## معماری

```
main.js       پروسه‌ی اصلی Electron — پنجره، IPC، خواندن/نوشتن فایل دیتابیس
preload.js    پل امن بین پروسه‌ی اصلی و رابط کاربری (contextIsolation فعال)
index.html    تمام رابط کاربری، منطق برنامه و کوئری‌های SQL
vendor/       کتابخانه‌های شخص ثالث، به‌صورت محلی و نسخه‌دار
```

### جریان داده

دیتابیس در حافظه با [sql.js](https://github.com/sql-js/sql.js) (پیاده‌سازی WASM از SQLite) نگه داشته می‌شود. پس از هر تغییر:

```
تغییر در UI → SQLite در حافظه → export به base64 → IPC → نوشتن اتمیک روی دیسک
```

نوشتن به‌صورت **اتومیک** انجام می‌شود: ابتدا در فایل موقت + `fsync`، سپس `rename`. پیش از جایگزینی هم نسخه‌ی قبلی در `shima-academy.sqlite.bak` نگه داشته می‌شود. بنابراین اگر برنامه وسط نوشتن کرش کند یا برق برود، فایل اصلی سالم می‌ماند و در بدترین حالت داده‌ها از نسخه‌ی پشتیبان بازیابی می‌شوند.

برای کاهش نوشتن‌های پیاپی، ذخیره‌سازی ۴۰۰ میلی‌ثانیه زمان‌بندی می‌شود و پیش از بستن پنجره flush می‌گیرد.

### امنیت Electron

- `contextIsolation: true`
- `nodeIntegration: false`
- تنها چهار کانال IPC مشخص در `preload.js` در دسترس رابط کاربری قرار می‌گیرد

## وابستگی‌های vendored

هیچ‌کدام از اینها در زمان اجرا از اینترنت بارگذاری نمی‌شوند؛ همه در `vendor/` قرار دارند:

| کتابخانه | نسخه | مجوز | نقش |
|---|---|---|---|
| [sql.js](https://github.com/sql-js/sql.js) | 1.13.0 | MIT | موتور SQLite در WASM |
| [lucide](https://lucide.dev) | 1.47.0 | ISC | آیکون‌ها |
| [Vazirmatn](https://github.com/rastikerdar/vazirmatn) | 33.0.3 | OFL 1.1 | فونت فارسی |
| [jalaali-js](https://github.com/jalaali/jalaali-js) | 2.0.1 | MIT | تبدیل تاریخ میلادی به جلالی |

### درباره‌ی `sql-wasm.wasm.js`

Electron صفحه را با `loadFile()` باز می‌کند، یعنی از origin `file://`. در این حالت Emscripten نمی‌تواند فایل `.wasm` را با `fetch` بخواند. به همین دلیل بایت‌های WASM در فایل `vendor/sql.js/sql-wasm.wasm.js` به‌صورت base64 جاسازی شده‌اند و مستقیماً به‌عنوان `wasmBinary` به `initSqlJs` داده می‌شوند — بدون هیچ درخواست شبکه‌ای.

اگر پروژه را روی یک وب‌سرور `http` باز کنید، همان مسیر `locateFile` به‌عنوان fallback عمل می‌کند.

### بازتولید فایل‌های vendor

پس از ارتقای نسخه‌ی sql.js یا jalaali-js:

```bash
npm run rebuild:vendor
```

این دستور `sql-wasm.wasm.js` را از `sql-wasm.wasm` و `jalaali.js` را از پکیج npm بازتولید می‌کند.

## ساختار دیتابیس

```sql
students(id, first_name, last_name, phone, grade, field,
         advisor, status, score, progress, created_at)
plans   (id, student_id, date, subject, title, duration, status)
exams   (id, student_id, title, date, score)
notes   (id, student_id, text, date)
```

- `status` در `students`: `active` / `warning` / `inactive`
- `status` در `plans`: `pending` / `done`
- `score` در `students`: **میانگین** تراز همه‌ی آزمون‌های همان دانش‌آموز (به‌صورت خودکار بازمحاسبه می‌شود)
- همه‌ی تاریخ‌ها به رشته‌ی جلالی `YYYY/MM/DD` ذخیره می‌شوند

حذف یک دانش‌آموز، برنامه‌ها، آزمون‌ها و یادداشت‌های مرتبط با او را هم حذف می‌کند.

## پشتیبان‌گیری

از صفحه‌ی **تنظیمات → داده‌ها → خروجی دیتابیس** یک فایل `shima-academy.sqlite` دریافت کنید. این فایل را می‌توان با هر ابزار SQLite خواند.

علاوه بر آن، برنامه به‌صورت خودکار یک نسخه‌ی `.bak` در کنار فایل اصلی نگه می‌دارد.

## وضعیت پروژه

این پروژه در حال حاضر **تست خودکار و CI ندارد**. تغییرات را پیش از ادغام، دستی با `npm start` بررسی کنید.

محدودیت‌های شناخته‌شده:

- تمام منطق در یک فایل `index.html` (حدود ۶۰۰ خط) قرار دارد و تفکیک نشده است

- رمزگذاری روی فایل دیتابیس اعمال نمی‌شود
